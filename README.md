# 家用电器售后工单 Agent

这是一个本地运行的家用电器售后工单分析项目。运营客服上传一份工单 JSON 后，FastAPI 校验并保存案例，LangChain 单 Agent 按需调用只读查询工具，生成基于订单、型号、物流、退款记录和售后规则的事实说明、处理建议及回复草稿。SQLite 保存每次运行，网页会自动展示分析结果。

当前六条合成样例覆盖：电热水壶物流停滞、洗衣机未发货、冰箱外观损坏、电饭煲渗水、吸尘器缺少配件、微波炉退款状态查询。样例中的品牌、商品型号、金额、轨迹和规则均为开发构造，不代表真实交易或品牌政策。

## 边界

- 工单与业务资料为本地上传样例；没有真实店铺、支付、仓储或物流接口。
- 退款申请和金额决定交人工；Agent不批准、不执行退款，不发消息、不派单、不结单。
- 退款状态答复只引用核实到的退款流水；流水成功不等于已确认支付渠道到账。
- 渗水、破损、异味、冒烟或异常发热时，回复建议停止使用、不要通电或自行拆机。Agent不诊断故障、不指导维修。质保与退换政策须有经核实的具体型号资料。
- 页面分析完成不代表工单已解决。缺规则、照片或其他业务资料可以是分析完成后的待办。

## 本地运行

建议 Python 3.12，在 PowerShell 中执行：

```powershell
cd D:\codex\project\cleaning-ticket-agent
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
$env:DEEPSEEK_API_KEY = "你的密钥"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

浏览器打开 `http://127.0.0.1:8000`，每次上传 `data/case-001.json` 至 `case-006.json` 中的一份。一次只支持一份 UTF-8 JSON 单工单，最大 1 MiB；仅接受 `metadata.synthetic=true` 的数据样例。停止服务按 Ctrl+C。应用不会自动加载 `.env`，请只在本机进程环境中设置密钥，不要提交密钥。

启动时检查本机密钥及模型名称配置；缺失或明显格式错误时，上传页提前提示，新分析接口返回503且不保存工单。配置问题修复后从已配置环境的终端重启服务。`/health` 检查服务和数据库，`/ready` 额外检查本机模型配置；自检不调用模型，ready不代表已验证密钥有效、服务连通或额度充足。配置缺失不影响查看历史结果。

分析中的结果页每2秒更新；终态停止刷新。刷新只读取已有运行，不重复导入或调用模型。新样例须重新上传生成新运行，已保存的历史运行不会被改写。

## 检查与评估

```powershell
python -m pytest tests -q
python -m evals.run_evals
python -m evals.run_evals --offline-replay
```

默认 `run_evals` 检查固定输入结构；`--offline-replay` 用预设判断经过实际工具、校验、工作流和 SQLite，验证数据流，不证明模型理解正确。

默认数据集为 `evals/datasets/independent20/inputs/` 下20条独立新工单，人工预期单独保存，不读取 `data/` 的六条演示工单。覆盖20种家电、不同语气、多轮更正、部分退款、记录冲突及安全边界；清单见该目录 `manifest.json`。旧的20条作为开发回归集保留，执行时增加 `--suite regression`。两组分数分别记录，不能直接作前后对比。

配置 `DEEPSEEK_API_KEY` 后可执行真实模型评估，会产生 API 费用：

```powershell
python -m evals.run_evals --live
```

模型结果仍需客服/开发者逐条检查事实、工具选择、退款边界、电器安全提示和型号政策依据。没有计价依据时成本标记为 unknown。

评估数据库和日志保存在 `runtime/`，与网页运行记录分开且不应提交。测试、离线评估与真实模型业务效果分别记录；旧文档中的历史测试数字发生在六条样例迁移前，不能作为家电场景当前验证结果。

提示词当前版本为3.3。评估器v5分别报告最终业务检查、无纠正严格检查、原始分类一致性及显式安全检查；支持显式预期核对事项和关键安全提示。具体预期变更见 `evals/评估集版本记录.md`。新报告名称为 `runtime/evals-live-数据集-时间戳-summary.json`，保留旧报告供比较。

模型格式错误最多重试一次，仍受总时限和调用次数限制；失败时保留已记录用量，缺少API用量信息时标记为不完整。运行库首次打开会自动增加独立的 `metrics` 字段，保留历史结果。条件退款尚未到期显示等待到期，需要客服到期后重新核查；系统不会自动监控条件。

临时连接错误、超时、429及5xx错误在一次分析内合计最多重试一次，等待0.5秒；认证和参数错误不重试。每次请求超时取30秒与剩余90秒总预算的较小值，等待和格式恢复也计入总预算；无响应的失败调用实际计费用量可能未知。

客户描述包含漏水、焦味、异常发热、玻璃裂纹等已覆盖风险词时，页面优先显示固定停用提醒，成功草稿也将提醒置于金额和补证前；即使模型服务失败仍保留安全提醒和明确失败状态。提示只依据客户文字作预防，不确认故障原因；关键词覆盖仍有遗漏及误触发可能，不能替代客服安全核查。

新分析结果将“客户需补充”与“资料与能力状态”分开：照片、条件说明等客户补证单独展示；未查询、查询无资料、正常无记录、能力未接入、资料冲突及技术问题进入可展开区域。当前运行通过 `information_gaps` 保存分类，`development_gaps` 供后续开发整理；尚未自动跨工单汇总。历史结果保留原展示，新分类需要重新分析生成。

## 项目结构

`agents/` 管模型判断，`workflows/` 管流程状态，`tools/` 只读查询，`context/` 管输入和事实约束，`prompts/` 存分模块版本化提示词，`tests/` 验证代码，`evals/` 验证业务行为。当前不启用跨工单长期记忆或 RAG；小规模样例使用 JSON，运行记录使用 SQLite。

开发进程、历史遗留问题和待办见 [docs/开发进程.md](docs/开发进程.md)。开发规范见 [AGENTS.md](AGENTS.md)，Git 入门见 [docs/Git入门.md](docs/Git入门.md)。Agency Agents 仅用于开发辅助，不进入运行时 Agent 流程。
